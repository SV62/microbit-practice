Words you'll see in the book

InputSomething the micro:bit notices: a button press or a shake.
OutputSomething it does back, like lighting up its 25 LEDs.
VariableA named box that holds a value that can change, like a score.
SelectionChoosing what to do with if… then… else.
IterationRepeating steps. Also called a loop.
EventA block that waits for something to happen, like on button B pressed.
Lesson 1 · Programming task 1

Counting button presses with a variable

The program keeps a number called Count. Each time button A is pressed, Count goes up by 1 and the new number appears on the screen.

The code (same as the book)
on start
set Count to 0 show number Count
forever
if button A is pressed then
set Count to Count + 1 show number Count
Pretend micro:bit
Count0

The program has started. on start set Count to 0. Press button A.

In everyday words

It works like a tally counter at a door. When the program starts, you set the counter to zero. Every time someone walks in (button A), you click it once and read the new number.

on start runs one time, when the micro:bit is switched on. forever keeps repeating, checking again and again whether button A is being pressed.

Things to try

  • Press A three times. Does the screen show 3, as your daughter predicted in the book?
  • Press B. Nothing happens, because the code only checks button A.
  • Count past 9. Real micro:bits scroll bigger numbers across the screen, and so does this one.
  • Unplug the battery, then plug it back in. The program is still saved, but Count starts again at 0 because on start runs again.

Lesson 2 · Selection

If it's shaken, show a sad face. Else, a happy face

An if… then… else block asks a yes/no question, called a condition. If the answer is yes (True), it runs the top part. If the answer is no (False), it runs the else part.

The code (same as the book)
forever
if is shake gesture then
show icon
else
show icon
Pretend micro:bit
is shake gesture? FALSE

Not being shaken, so the else part runs and shows a happy face.

In everyday words

"If it's raining, take an umbrella. Otherwise, take sunglasses." You only ever do one of the two, and which one depends on the answer to the question.

The if block sits inside forever so the micro:bit checks the question all the time, not just once.

Things to try

  • Press Shake it and watch the yellow outline jump from the else part to the top part.
  • When the shaking stops, the condition is False again and the happy face returns.
  • Ask: what if we swapped the two faces? The program would be happy when shaken.

Lesson 3 · Iteration

Flash an arrow 4 times with a loop

When button B is pressed, the repeat block runs the steps inside it 4 times. Each time it shows an arrow, waits, clears the screen and waits again, which makes the arrow flash.

The code (same as the book)
on button B pressed
repeat 4 times
show leds pause (ms) 200 clear screen pause (ms) 200
Pretend micro:bit
Waiting for button B

Nothing happens until button B is pressed. That press is the event.

In everyday words

Instead of writing "clap, clap, clap, clap" you write "clap 4 times". A loop saves you from writing the same instructions again and again.

A pause of 200 ms is a fifth of a second. Without the clear screen block the arrow would stay lit and you would not see it flash.

Things to try

  • Press button B and count the flashes. Tick Slow motion to follow each block.
  • Change the number to 2 or 7. The code changes, and so does the number of flashes.
  • Press button A. Nothing happens, because the program only listens for B.
